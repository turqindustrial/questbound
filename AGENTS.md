# Questbound delivery preferences

- Whenever sharing the playable game, provide separate labeled **Desktop** and **Phone** links, as requested by the user. Keep both on the same current source version.
- The name is changing (October 2026): the host is choosing a new name for the game (Fablebound, or an alternative); "Eternal Tales" was dropped because it is a registered trademark in Ireland and the UK for games. Until the host confirms the new name, the product is still called Questbound in code, file names, storage keys (`questbound.*`), services, the launcher and these notes: rename nothing until the host says which name it is.
- Desktop development normally runs at `http://localhost:8081/`. Phones use only the encrypted HTTPS share link (`Questbound-Share.cmd` / `launch.ps1 -Share`, served by `phone-server.cjs --public <https origin>`), never localhost or a LAN address: the plain-HTTP Wi-Fi gateway is retired (`phone-server.cjs` without `--public` refuses to start, and a remote plain-HTTP request gets 426). Read `.questbound-share-session.json` for the current link, invite code and expiry; verify the share process and its tunnel are running before presenting it as live. Do not reuse stale links or codes.
- Rebuild `dist-phone` with `npm.cmd run build:web` after changes before sharing an updated Phone link. `start-phone.cmd` now calls `Questbound-Share.cmd`; `npm.cmd run phone` builds and then only reports that remote HTTP play is disabled.
- Phone access requires the PC, the share gateway and its tunnel, the existing private DM service and the account service running. During the beta nobody has to sign in: a phone plays with an anonymous guest identity (see Guest play) and the gateway's `/usage` check with the account service accepts it; once `accountsRequired` is turned on, a phone needs a signed-in, verified account to ask the Dungeon Master. Saves stay in each browser (per account profile), with a copy on the player's account and a recovery-code copy; a campaign shares one table. Do not claim live cross-device sync of solo play or a tested native app.
- Keep the DM service and API credentials private on loopback. Phone clients use the paired same-origin `/api` gateway. Never serve workspace files as static content; only serve the web export directory.
- Test new UI at phone and desktop widths and check phone endpoint routing when changing AI, image, or character generation.
- `Questbound.cmd` (runs `launch.ps1`) starts everything and reuses running services: DM on 8084, the account and campaign service (`sync-server.cjs`, a shim over `account-server.cjs`) on 8086, desktop on 8081 (`desktop-server.cjs` serving `dist-phone` and proxying `/api/sync/*` to 8086, or Expo with `-Dev`), and with `-Share` the share gateway on loopback 8087 behind the tunnel. No Wi-Fi gateway is started (port 8085 is no longer used; `-TrustNetwork` only points to `Questbound-Share.cmd`). It rebuilds `dist-phone` when top-level sources are newer. `-Stop` stops only what it started. Services run in their own hidden consoles with logs in `.questbound-logs/`. `Apply-Security-Update.cmd` (`restart-game-services.ps1`, `restart-service-rules.ps1`, checked by `verify-restart-services.ps1`) restarts running services after a server change.
- The API key may be remembered only DPAPI-encrypted in `.questbound-key.dpapi` (user's choice at the launcher prompt); never write it in plain text or pass it on a command line. Never run the key prompt on the user's behalf.
- The shared table is a set of campaigns (see the security update at the end and Server turns and campaign edits): `campaigns.cjs` keeps each in `.questbound-table/campaigns/<32 hex>.json` (at most 100 campaigns, 12 members each), and browsers reach it only through `/api/sync/campaign-*` (the desktop server's proxy, or the share gateway on phones). A stale `baseVersion` gets a conflict answer with the newer state, which the browser adopts; a turn already running answers 423. Rejected AI replies are logged (mechanical fields only) to `.questbound-diagnostics.jsonl`.
- Internet sharing (`Questbound-Share.cmd` / `launch.ps1 -Share`) runs a Cloudflare quick tunnel to the share gateway (`phone-server.cjs --public <https origin>`, loopback port 8087) that accepts only that host/origin, sets Secure cookies, throttles pairing per `CF-Connecting-IP` plus a global 50-wrong-codes-per-hour brake, and caps each session at 60 non-art DM requests per 10 minutes (see Request limits). The gateway invite only opens the site: each player still signs in to a verified account and joins a campaign with its own invite. The share session file is `.questbound-share-session.json` (git-ignored). Never expose the DM, account or desktop servers directly, and never type an invite code into a page yourself.
- The DM server queues requests (default 3 at once, `QUESTBOUND_DM_CONCURRENCY`); art polls bypass the queue. Restarting the DM needs the user's key: ask the user to run the launcher, never run the key prompt yourself. A DM started with `start-dm.ps1` runs in the user's own PowerShell window and is not in the launcher's pid file: `Questbound.cmd -Stop` does not stop it (and would stop the tunnel, changing the testers' link), so the way to restart it is Ctrl+C in that window, then `Questbound.cmd`. Do not build a way for the DM to relaunch itself with its inherited key: that was tried on 2026-10-02 and stopped by the assistant's safety check; it needs the user's explicit approval. Only `generate` (and the modules it requires fresh) reloads per request; `createServer`'s HTTP layer changes only after a restart. Edit `dm-server.cjs`, its modules (`dm-instructions.cjs`, `dm-schemas.cjs`, `dm-replies.cjs`) and `adventure-generator.cjs` in a temp copy (the copy of dm-server.cjs requires the modules beside it), `node --check` and test it (`QB_DM=./copy node verify-dm-stream.cjs`), then copy it over: a syntax error breaks every tester at once.
- Turns and rests (`adventureRules.js`, `recoveryRules.js` (draughts drunk or given, `shortRest`, `longRest`), `classActions.js`, `verify-turns.cjs`): a turn in a creature fight is one action and one bonus action. A healing draught (drunk or given), Second Wind, Lay on Hands, a Monk's strike, the off-hand light weapon and bonus-action spells are bonus actions (`bonusOptions`; healing only counts when hurt). After the action, if a bonus action is worth offering, the engine sets `game.actionUsed` (and `game.dodging` for a Dodge) and waits: only a bonus action or `end-turn` is accepted, and a bonus action taken then ends the turn. With nothing to offer, the foe answers at once as before, so tests that expect that use fixtures without a draught, a hurt companion or uses (`potions:0`, `resources:{wind:2,surge:1}`; a Fighter of level 2+ also pauses while Action Surge is ready). `short-rest` follows Baldur's Gate 3 (`shortRestLimit`: two between long rests, three for a Bard of level 2+; half HP for the hero and each following companion, and a companion knocked down comes round; Second Wind, Action Surge, short-recharge subclass uses and Warlock slots back; `game.shortRests`). `long-rest` restores HP, slots, features and short rests and keeps everything else (world, people, pack, feed): never rebuild the adventure with `newAdventure` for a rest. `dmChoices(hero,game,health)` and `quickActions(hero,game,health)` take the hero's health so healing is only offered when hurt. `restWouldHelp` (dmChoiceRules.js) treats health null as full hit points, so no short rest is offered to the player or the Dungeon Master when there is nothing to recover: the engine refuses such a rest ("already rested"), and on 2026-10-03 the DM took "catch my breath" as one and the whole turn failed. The action economy (2024 rules, `verify-action-economy.cjs`) holds in creature fights, brawls and the party's turn order:
  - A turn is one action and one bonus action. `turnCost(hero,game,action)` says 'action', 'bonus' or 'free'. Extra Attack is part of the one Attack action. At most one spell slot is spent a turn (`slotSpentThisTurn`).
  - `castError` refuses an action spell once `game.actionUsed` is set, and under Action Surge, so dmCommand fails before any Dungeon Master ruling is asked for. `fightTimingError` keeps reactions and castings of a minute or more out of fights.
  - An improvised attempt (the Dungeon Master's check, `commitWorldCheck`) in a creature fight is the action: it runs `{type:'improvised'}` through adventureStep, so the turn pauses, the foe answers, or the party turn passes on. It is refused once the action is spent, and in brawls. dm-rules `validateGroundedReply` refuses such check replies too.
  - Giving a healing draught (`give-potion`, including a party Revive) is a bonus action like drinking one. `potionGifts` in classActions.js feeds `bonusOptions` and `bonusChoices`.
  - Action Surge (`surgeLimit`/`surgeReady`, choice `class:surge`, typed "action surge"): a Fighter of level 2+ takes it once the action is spent. It clears `actionUsed` and sets `game.surged` and `resources.surge` (twice per rest from level 17, once a turn). The extra action can never cast a spell or work a magic item. The turn pauses while it is ready. A short rest restores it. Long rests, `endHeroTurn` and `fightOver` clear `surged`, which is a party turn field. Saves allow `surged` only in stage combat, and dodging with `actionUsed` or `surged`.
  - In a brawl a draught, a stronger draught, Second Wind, Lay on Hands, a bonus-action spell or a draught given to someone is a bonus action taken before the action (which still ends the turn there). The people fighting do not answer it.
  - A typed sentence with two moves (`splitTurn`/`twoMoves` in dmCommands.js, never inside a spell's own name): two blows at one target are one attack; in a fight an action plus a bonus or free move is `{type:'turn',steps:[a,b]}`, played by `wholeTurn` while the turn is still the hero's; anything more resolves the first move, with a 'Not this turn: "…" must wait for your next turn' line ('One thing at a time' out of fights).
  - `turnLeft(hero,game)` goes to the Dungeon Master as `turnResources.left` (with `attacksPerAction` and `actionSurge`) and into `context.now`. The Cast… picker offers only spells `castableNow` accepts. The opening attack stays a turn of its own (house rule).
- Speaking to the Dungeon Master (`turnMemory.js`, `verify-direct.cjs`): the DM switch beside the message box, or a message starting "DM," / "(ooc)", sends `context.outOfCharacter` (`canRewind`, `lastTurn`); the server answers out of character, changes nothing, and may return `rewind:true`, and `fault:true` when the player reports, or the DM admits, something the game got wrong (the game then offers to tell the host). `Adventure.act(action,conversation,random,{from})` then applies the exchange to the state remembered before the player's last turn (`rememberTurn`/`turnToRewind`: one turn deep, in memory only, never at a shared table). The exchange is an ordinary no-action turn (`conversation.direct`), so it shows in the feed and the journal. When the Dungeon Master cannot be reached, `offline()` in `useDmTurn.js` tells the host what to start and a guest only that it is not answering (the old "open your private AI setup window" confused phone players).
- Typing on phones (`webLayout.js`): `#root` is pinned to the visual viewport (`--questbound-height`, `--questbound-top`), so the message box rests above the keyboard on Android and iOS. While the message box is focused on a touch device (`touchKeyboard`), `DungeonMaster` reports `onTyping`: the battle buttons, the Suggestions bar, feed header, bottom tabs and (on short screens) the HUD and strips step aside, and the feed stays on its last lines when its height changes. Controls beside a field carry `dataSet={{keepfocus:'true'}}` so a tap does not blur the field first (a blur closes the keyboard, moves the control and loses the tap). Fields in scrolling pages are scrolled into view when the visible height shrinks; dialogs (`data-qb=scrim`) are sized to the visible area. While a keyboard is up the bottom safe-area inset is dropped (`--sa-b` 0; see Filling the screen). Test by focusing a field and resizing the viewport to about 375×400.
- Filling the screen (`webLayout.js`, `public/index.html`, `public/manifest.json`, `theme.js`/`themeRules.js` `pageBackground`, `DisplayControls.js` `HomeScreenHelp`, `verify-fit.cjs`; 2026-10-11, the host's words: "double check that the game fits properly on all phones and is able to fill the full screen"): the page is `viewport-fit=cover`, so the game draws under the notch, rounded corners and home indicator (before this, `#root` carried the insets as padding and every screen had a bare ink strip top and bottom). `#root` is never padded; the safe-area insets are style variables (`--sa-t/r/b/l` from `env(safe-area-inset-*)`, `--sa-b` 0 while a keyboard is up) given as transparent borders to the screens' frames (`dataSet={{safe:'pad'}}` on App.js's two shells and the launch card; every `[data-qb=scrim]`, the story cover included), so backgrounds still fill the insets while content stays clear. The HUD and the phone tab bar reach into the insets beside them (negative margins plus borders, `background-origin:border-box`; removing the two `html [data-qb=hud|tabbar]` rules in webLayout.js brings back a plain strip if the host prefers it); floating cards near the top (deeds, experience: CinematicLayer.js) carry `dataSet={{safe:'top'}}`; a sheet inside a scrim is capped at `max-height:100%`. A new full-screen layer or dialog must take one of these, never pad `#root`. `index.html` carries the Home Screen tags statically (`theme-color`, `mobile-web-app-capable`, `apple-mobile-web-app-capable`, black-translucent status bar, `apple-mobile-web-app-title`, `format-detection`; the viewport also says `interactive-widget=resizes-content`; `fullscreen.js` adds them only when missing), and theme.js keeps `theme-color` to the page's ink in each theme and mode (`pageBackground(theme,mode)`), so the phone's bars match the page. The manifest (`"id": "/"`) opens installs full screen (`display_override` fullscreen, standalone) in any orientation. iPhone pages cannot use the Fullscreen API: `HomeScreenHelp` (the menus' corner button, Settings → Display, and on an iPhone not running from the Home Screen the pause menu's Full screen cell) explains Add to Home Screen (Share under ••• in newer Safari), scrolls on a phone held sideways, and says the Home Screen game keeps its own saves apart from Safari's (carry a hero with Move your hero); Android and desktop keep the real full-screen toggle. On Android a browser page cannot hide the address bar without the Fullscreen API (the page never scrolls), so the Full screen button or installing is the way. The invite page in phone-server.cjs keeps its own insets (`max(16px, env(safe-area-inset-*))` per side), a clamped title (`clamp(24px,8.6vw,34px)`) so it fits 320 px, and a 96 px seal on a phone held sideways (a change there needs a share-gateway restart). Choice cards in the builder (`CharacterBuilder.js`, whose step track is 28 px tall to tap), the ready-made hero cards (`QuickHeroes.js`) and the Inventory's equipment slots shrink (`flexShrink:1`, `minWidth:0`) rather than run off a 320 px screen or a phone held sideways. `verify-fit.cjs` checks all of this statically; on 2026-10-11 every screen from the boot card to dying was measured at twelve phone sizes (320×568 to 932×430) with iPhone insets in headless Chrome (CDP `Emulation.setSafeAreaInsetsOverride`, mobile emulation, `getBoundingClientRect`/`elementFromPoint`: no sideways scroll, nothing off screen or under an inset, no overlapping controls, no bare page at the edges). A real device was not available.
- Lands and maps (`mapRules.js`, `mapLayout.js`, `mapArt.js`, `AdventureMap.js`, `verify-regions.cjs`, `verify-map-layout.cjs`): every written story has its own `story.geography` (where its three starting places lie and which are joined: a line, a fork or a loop), made by `makeGeography` from the story writer's `layout` or from the story id; a save without one keeps the old fixed triangle (`mapCoordinates`; only stories from before geographies: a game with no story at all is never played, see No crossroads). The writer also gives the land a name and a terrain (`story.region`, `story.terrain`; `terrains`), a kind for each of the three places, up to six `landmarks` that `freshStoryGame` puts on the map as unvisited places (`maxLandmarks`), and one or two `lands` beyond this country (`farLandPlaces`: each a region `r1`/`r2` with one known place 15 to 300 miles from the start, joined to it by a road). Places lie a little off their compass bearing (seeded, repeatable). Regions: the home region plus `game.world.regions` (`r1`…`r99`, at most 59: `maxRegions` 60 with home, never forgotten; see Beyond the map); a place carries `region` and inherits it from where it was found; the DM's `discovery.region` ({name, terrain}, miles up to 300) opens a new land, and a sequel turns the earlier country into a region of its own. `regionLayout(game,w,h,{region})` lays out one region's sheet and returns `exits` (roads to other regions, drawn to the edge and tappable); `regionMapSvg` draws it to suit the terrain (`mapThemes`: sea along a coast, a river, ranges, woods, pools, cavern walls, all seeded). Long roads are walked eight hours a day (`travelRoute`). `regionLabels` names what fits; `RegionSheet` zooms and `Full map` opens it in a dialog.
- Beyond the map (2026-10-11, the host's words: "make sure travel is possible outside of the region of the map, with more map generated outside if the player decides to move to a new map. then make sure the game remembers the old map when a new one is generated, there can be a limit to this"; `mapRules.js` `beyondError`/`edgePlace`/`beyondPlan`/`goBeyond`/`roomToMake`/`letRumoursGo`/`mapHasRoom`/`discoveryRoom`, `dmChoiceRules.js` `beyondChoices`/`mapMoves`, `dmSceneRules.js` `placesNamed`/`withNamedJourneys`, `AdventureMap.js` `BeyondCard`, `verify-beyond.cjs`): `{type:'beyond',bearing}` (`beyondStep` in travelRules.js, with the arrival ambush check, the victory-stage scene and the brawl block that travel has) takes the hero off the edge of the land they are in: a new region (a name and terrain from our own word lists, leaning by direction, never the land just left) joined by a road from the place of this land farthest that way (`edgePlace`), an arrival place 25 to 70 miles on (usually a town or camp) and one or two places heard of a few miles further (some risky); all seeded from the story id, land, edge place, direction and map size (`beyondPlan`), so every device and the campaign server agree; the walk follows `travelRoute` (eight hours a day, so a day to three). Offered as `beyond-N`…`beyond-NW` in `dmChoices` (never chips: `quickActions` skips them; dropped before journeys when the list passes thirty), typed ("I head north beyond the map": dm-intent's "beyond the map" second look, settled by the game when a direction is named and its choice is offered, else the model is asked which way), or from the map's Beyond the map compass (`BeyondCard`, under the current land's sheet and on the Full map: eight ways, disabled where the game refuses; pick, then Set out; its card says "Lands you leave stay on your map, and you can always travel back."). Lands travelled are never forgotten (2026-10-12, the host's words: "previous lands travelled should not be forgotten. a player should be able to return to those lands."; the old `landsToForget`/`forgetLand`/`forgetLands` and their "The memory of <land> fades." are gone): up to sixty lands (`maxRegions` 60: home and r1…r99) and 150 places (`maxWorldPlaces`, ids p1…p999, save pattern `p\d{1,3}`; coordinates up to 1e9 ft) are kept, and regions carry `last` (map minutes at the last arrival, set in `travelTo`). When something new needs room (`roomToMake`, worked out once per game) only what the hero merely heard of gives way (`letRumoursGo`/`discoveryRoom`): a place never visited with nothing found from it (so no road back runs through it), nobody living there, no companion waiting, no fallen unsearched, not where the hero stands, not the errand's place, not one the tale still names (chapter under way or next, open leads, errand), never the last place of its land (other lands' rumours first, oldest first); or a whole land never reached (none of its places visited or kept, not named by the tale, no road to another land through it), oldest first. The log (not the story log) says "Your map is full, so the rumour of X fades from it: you never went there." or "Word of <land> fades from your map: you never went there." When nothing may give way (the hard cap) the road beyond goes no further ("The road goes no further: your map is full, and every land and place on it is one you have been to or still need. Travel back to a land you know."; no beyond choices), a DM discovery is refused ("Your map is full: …") and `canDiscover` is false; with only the lands full a far discovery joins the land the hero is in. Every place stays travelable; in practice 150 places is some 50 to 60 lands of beyond trips. New ids are the first free ones (`freePlaceId`, `freeRegionId`, `freePersonId`), never ids let go in the same turn. `travelChoices` adds the nearest place of every other land (past thirty choices the farthest give way); `dmContext(hero,game,health,input)` adds the journey to any land or place the player's words name (`placesNamed`: the whole name, "the" optional; `withNamedJourneys`, dropping a far journey or a way beyond to stay within thirty), and useDmTurn.js and server-turn.cjs pass the input and look an `actionId` up in `dmChoices` plus `mapMoves`; `mapMoves(game)` is every journey a road reaches plus the ways beyond, which the map's Travel buttons send and `commitDmTurn` and the campaign server (`server-turn.cjs`; `rules-engine.cjs` exports it) accept, so any land can be travelled back to: on the map, among the choices, by name, solo or at a table. Saves from before load as they were (r1…r19, p1…p99 and n1…n48 sit inside the new patterns); a land an older build let fade cannot be brought back, and its old "fades" lines stay in that save's log. Routes (`routeMemo`: one Dijkstra per start place while the places array is the same), place look-ups (an id index per places array), `npcIdsOf` (per `game.people` object) and room are worked out once, so the DM context for the largest world takes about 120 ms. The map's row of lands puts the land the hero is in first, then the one on show, home, and the rest by last visit (Show all: four lines, `openRows={4}`, then it scrolls). A first arrival in a land pays experience only with a place that still pays (ten a tale), so walking off the map again and again is no way to level. The DM gets BEYOND THE MAP in FAR JOURNEYS (select the beyond choice; a `discovery.region` only for a land the player names; narrate the days on the road and the arrival as the game names it; bring someone in at a town; lands travelled are never forgotten: to go back select the travel choice, else return discovery with that place's exact name, its land as region and travel true, which walks there; a rumour the game let go was never visited), `context.world.landsRemembered` and `context.world.farLands` (see Who is here); dm-intent counts farLands place names when deciding whether a word names one place. New lands keep the names the game gives them (the DM describes, never renames).
- Species (`characterRules.js` `species`/`speciesTraits`/`speciesProfile`/`heroSpecies`/`fixedLineage`/`baseSpeciesOf`/`speciesSkills`, `verify-species.cjs`; the host on 2026-10-11: "make sure wood elf and high elf are two different classes with their respective values"): the elves are three species of their own, High Elf, Wood Elf and Drow, each the SRD 5.2 Elf with its lineage (`fixedLineage`: High Elf, Wood Elf, Drow; the builder shows no lineage picker for them) and `baseSpecies` 'Elf' (`baseSpeciesOf`, for anything keyed on elves), listed together in the builder as the Elves (`speciesGroups`: one bordered panel with a heading and a line about elves, at the place of the first, between Dwarf and Gnome; `optionCards` takes groups; the host on 2026-10-12: "maybe drow should be listed under the elves with the others."). Plain 'Elf' and 'Dark Elf' (the Drow's stored name until 2026-10-12; new heroes store 'Drow') are in `legacySpecies`: a hero made as one stays valid and is never rewritten (the adventure save is tied to the hero's exact JSON); `heroSpecies(hero)` reads an old Elf as the species its lineage names, or a High Elf when it has none (30 feet as before, plus the High Elf spells), and an old Dark Elf as a Drow (`speciesName` for a bare name, e.g. a roster summary), and the builder turns either into that species when the hero is edited. Nothing on screen says "Dark Elf" or "Dark Elf (Drow)". Show a hero's species with `heroSpecies`, never `hero.species` (App.js, the story writer's `context.player.species`, GameHud, Inventory, HeroRoster, the epitaph, CharacterSheet, entityRules, partyRules, taleRules and dmContext do); portraits (`worldArtRules`), the regard seed and feedback records keep the raw species, so nothing is repainted or re-rolled. `speciesTraits` gives every species its size, speed, darkvision and traits in our own words, each marked whether the rules play it (`played: 'game'`: Dwarven Toughness, species spells, size, Keen Senses) or the Dungeon Master weighs it (`'story'`: Fey Ancestry, Trance, Halfling Luck, Relentless Endurance and the rest); `combatBasics` returns `speed`/`speedFormula` (Wood Elf and Goliath 35 feet; Chain Mail without Strength 13 takes 10 off), `darkvision` (Dwarf, Orc and Drow 120) and `size`; nothing in the engine moves by feet, so speed is shown and told, not rolled. The builder's species cards, the Character Sheet's species panel and `context.player.speciesTraits` {size, speed, darkvision, traits} show them. Every elf's Keen Senses trains Insight, Perception or Survival (`form.keenSense`, chosen on the builder's species page, Perception for elves made before; `trainedSkills` adds `speciesSkills`; `buildError` refuses it on a non-elf). `relationshipRules.js` has plurals and reputations for High Elf (as Elf) and Wood Elf (a little warmer), and for Drow under both names (plural 'drow', the old Dark Elf's weights; `regardMemory` says "A drow"; `sameKind` treats drow as dark elf, so elf, drow and dark elf people are kin to a Drow hero under either name). The ready-made wizard Ilyra is a High Elf. Checks that inject names for `entityRules.js`/`partyRules.js` need `heroSpecies`; `rules-engine.cjs` exports it.
- Reactions to the hero's kind (`relationshipRules.js`, `verify-regard.cjs`): `speciesRegard(game,id,hero)` is each person's view of the hero's species (kin, warm, curious, indifferent, wary, scornful, with a reason): written by the story writer or the DM (`regard` on the NPC or person) or drawn from who they are and how that species is commonly met (`reputations`, seeded; a human among humans is indifferent). It sets the first impression (`firstImpressions`, `introducePerson(game,sketch,hero)`), sways Persuasion, Deception and Performance aimed at that person (`regardSway`: +2 to −3, until they are won over), reaches the DM as `regardsYourKind`, and shows in the People panel while it still says something true.
- Portraits and gender (`worldArtRules.js`): NPCs and people carry `gender` (woman, man, other) from the writer or the DM; without it `genderOf` reads their appearance (a hero's description, then backstory). A woman's portrait description opens by saying she has no beard, any facial hair written into it is cut, and her art id gets `-w` so portraits painted before this are painted afresh. Never write a beard into a woman's appearance (the built-in captain once had a "beard ring"). A ready journey's own subjects (its three places, keeper and mara, its residents by name as `resident-<slug>`, and its main foe) are painted under `story.artId` (`artCampaign`/`residentArtId` in worldArtRules.js), once for every player of that journey; people and places met in play keep the copy's own story id. `validStory` accepts `libraryId` (uuid) and `artId` (`'journey-'+libraryId`). A journey's card cover is its opening place's picture (the same key as the opening scene). A person with a library face (a `pool` id or a look-alike) is not painted at all; see The people library and Look-alike portraits and shared creatures.
- The story log (`storyLog.js`, `journalRules.js`, `verify-story-log.cjs`): `game.storyLog` holds one short line per major event (place found, reached or returned to, person met, joined or lost, fight begun and how it ended, deaths, grudges and debts, gold and finds, rests, levels, the end of the tale), worked out by `storyEvents(before,after,hero,{action})` and appended by `withStoryLog` (in `settleTurn`, see Server turns); level-ups and new chapters append their own lines. The Log tab shows it newest first; the engine's raw lines sit under "Latest rolls and rulings".
- The story so far, remembered for good (`memoryRules.js`, `verify-memory.cjs`; the host, 2026-10-13: "fix the dungeon master's memory so that it remembers everybody's adventure from start to finish"):
  - **The chronicle.** `game.memory` (save and shared world, never a hero field) keeps the chronicle: every tale `{no, title, status, began, summary?, chapters:[{n, title, done, beats, folded}]}`, folded by the engine from the story log as turns settle (`withMemory` in `settleTurn`, after the deeds; `memoryOf` folds lazily anything not yet seen and builds an old save's memory from its storyLog, storyHistory and "Previously" note; an old save's memory is also built once when it is upgraded, see Saves and their formats).
