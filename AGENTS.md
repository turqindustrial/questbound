# Questbound delivery preferences

- Whenever sharing the playable game, provide separate labeled **Desktop** and **Phone** links, as requested by the user. Keep both on the same current source version.
- Desktop development normally runs at `http://localhost:8081/`. Phones use only the encrypted HTTPS share link (`Questbound-Share.cmd` / `launch.ps1 -Share`, served by `phone-server.cjs --public <https origin>`), never localhost or a LAN address: the plain-HTTP Wi-Fi gateway is retired (`phone-server.cjs` without `--public` refuses to start, and a remote plain-HTTP request gets 426). Read `.questbound-share-session.json` for the current link, invite code and expiry; verify the share process and its tunnel are running before presenting it as live. Do not reuse stale links or codes.
- Rebuild `dist-phone` with `npm.cmd run build:web` after changes before sharing an updated Phone link. `start-phone.cmd` now calls `Questbound-Share.cmd`; `npm.cmd run phone` builds and then only reports that remote HTTP play is disabled.
- Phone access requires the PC, the share gateway and its tunnel, the existing private DM service and the account service running. During the beta nobody has to sign in: a phone plays with an anonymous guest identity (see Guest play) and the gateway's `/usage` check with the account service accepts it; once `accountsRequired` is turned on, a phone needs a signed-in, verified account to ask the Dungeon Master. Saves stay in each browser (per account profile), with a copy on the player's account and a recovery-code copy; a campaign shares one table. Do not claim live cross-device sync of solo play or a tested native app.
- Keep the DM service and API credentials private on loopback. Phone clients use the paired same-origin `/api` gateway. Never serve workspace files as static content; only serve the web export directory.
- Test new UI at phone and desktop widths and check phone endpoint routing when changing AI, image, or character generation.
- `Questbound.cmd` (runs `launch.ps1`) starts everything and reuses running services: DM on 8084, the account and campaign service (`sync-server.cjs`, a shim over `account-server.cjs`) on 8086, desktop on 8081 (`desktop-server.cjs` serving `dist-phone` and proxying `/api/sync/*` to 8086, or Expo with `-Dev`), and with `-Share` the share gateway on loopback 8087 behind the tunnel. No Wi-Fi gateway is started (port 8085 is no longer used; `-TrustNetwork` only points to `Questbound-Share.cmd`). It rebuilds `dist-phone` when top-level sources are newer. `-Stop` stops only what it started. Services run in their own hidden consoles with logs in `.questbound-logs/`. `Apply-Security-Update.cmd` (`restart-game-services.ps1`, `restart-service-rules.ps1`, checked by `verify-restart-services.ps1`) restarts running services after a server change.
- The API key may be remembered only DPAPI-encrypted in `.questbound-key.dpapi` (user's choice at the launcher prompt); never write it in plain text or pass it on a command line. Never run the key prompt on the user's behalf.
- The shared table is a set of campaigns (see the security update at the end and Server turns and campaign edits): `campaigns.cjs` keeps each in `.questbound-table/campaigns/<32 hex>.json` (at most 100 campaigns, 12 members each), and browsers reach it only through `/api/sync/campaign-*` (the desktop server's proxy, or the share gateway on phones). A stale `baseVersion` gets a conflict answer with the newer state, which the browser adopts; a turn already running answers 423. Rejected AI replies are logged (mechanical fields only) to `.questbound-diagnostics.jsonl`.
- Internet sharing (`Questbound-Share.cmd` / `launch.ps1 -Share`) runs a Cloudflare quick tunnel to the share gateway (`phone-server.cjs --public <https origin>`, loopback port 8087) that accepts only that host/origin, sets Secure cookies, throttles pairing per `CF-Connecting-IP` plus a global 50-wrong-codes-per-hour brake, and caps each session at 60 non-art DM requests per 10 minutes (see Request limits). The gateway invite only opens the site: each player still signs in to a verified account and joins a campaign with its own invite. The share session file is `.questbound-share-session.json` (git-ignored). Never expose the DM, account or desktop servers directly, and never type an invite code into a page yourself.
- The DM server queues requests (default 3 at once, `QUESTBOUND_DM_CONCURRENCY`); art polls bypass the queue. Restarting the DM needs the user's key: ask the user to run the launcher, never run the key prompt yourself. A DM started with `start-dm.ps1` runs in the user's own PowerShell window and is not in the launcher's pid file: `Questbound.cmd -Stop` does not stop it (and would stop the tunnel, changing the testers' link), so the way to restart it is Ctrl+C in that window, then `Questbound.cmd`. Do not build a way for the DM to relaunch itself with its inherited key: that was tried on 2026-10-02 and stopped by the assistant's safety check; it needs the user's explicit approval. Only `generate` (and the modules it requires fresh) reloads per request; `createServer`'s HTTP layer changes only after a restart. Edit `dm-server.cjs` and `adventure-generator.cjs` in a temp copy, `node --check` and test it (`QB_DM=./copy node verify-dm-stream.cjs`), then copy it over: a syntax error breaks every tester at once.
- Turns and rests (`adventureRules.js`, `classActions.js`, `verify-turns.cjs`): a turn in a creature fight is one action and one bonus action. A healing draught (drunk or given), Second Wind, Lay on Hands, a Monk's strike, the off-hand light weapon and bonus-action spells are bonus actions (`bonusOptions`; healing only counts when hurt). After the action, if a bonus action is worth offering, the engine sets `game.actionUsed` (and `game.dodging` for a Dodge) and waits: only a bonus action or `end-turn` is accepted, and a bonus action taken then ends the turn. With nothing to offer, the foe answers at once as before, so tests that expect that use fixtures without a draught, a hurt companion or uses (`potions:0`, `resources:{wind:2,surge:1}`; a Fighter of level 2+ also pauses while Action Surge is ready). `short-rest` follows Baldur's Gate 3 (`shortRestLimit`: two between long rests, three for a Bard of level 2+; half HP for the hero and each following companion, and a companion knocked down comes round; Second Wind, Action Surge, short-recharge subclass uses and Warlock slots back; `game.shortRests`). `long-rest` restores HP, slots, features and short rests and keeps everything else (world, people, pack, feed): never rebuild the adventure with `newAdventure` for a rest. `dmChoices(hero,game,health)` and `quickActions(hero,game,health)` take the hero's health so healing is only offered when hurt. `restWouldHelp` (dmContext.js) treats health null as full hit points, so no short rest is offered to the player or the Dungeon Master when there is nothing to recover: the engine refuses such a rest ("already rested"), and on 2026-10-03 the DM took "catch my breath" as one and the whole turn failed. The action economy (2024 rules, `verify-action-economy.cjs`) holds in creature fights, brawls and the party's turn order:
  - A turn is one action and one bonus action. `turnCost(hero,game,action)` says 'action', 'bonus' or 'free'. Extra Attack is part of the one Attack action. At most one spell slot is spent a turn (`slotSpentThisTurn`).
  - `castError` refuses an action spell once `game.actionUsed` is set, and under Action Surge, so dmCommand fails before any Dungeon Master ruling is asked for. `fightTimingError` keeps reactions and castings of a minute or more out of fights.
  - An improvised attempt (the Dungeon Master's check, `commitWorldCheck`) in a creature fight is the action: it runs `{type:'improvised'}` through adventureStep, so the turn pauses, the foe answers, or the party turn passes on. It is refused once the action is spent, and in brawls. dm-rules `validateGroundedReply` refuses such check replies too.
  - Giving a healing draught (`give-potion`, including a party Revive) is a bonus action like drinking one. `potionGifts` in classActions.js feeds `bonusOptions` and `bonusChoices`.
  - Action Surge (`surgeLimit`/`surgeReady`, choice `class:surge`, typed "action surge"): a Fighter of level 2+ takes it once the action is spent. It clears `actionUsed` and sets `game.surged` and `resources.surge` (twice per rest from level 17, once a turn). The extra action can never cast a spell or work a magic item. The turn pauses while it is ready. A short rest restores it. Long rests, `endHeroTurn` and `fightOver` clear `surged`, which is a party turn field. Saves allow `surged` only in stage combat, and dodging with `actionUsed` or `surged`.
  - In a brawl a draught, a stronger draught, Second Wind, Lay on Hands, a bonus-action spell or a draught given to someone is a bonus action taken before the action (which still ends the turn there). The people fighting do not answer it.
  - A typed sentence with two moves (`splitTurn`/`twoMoves` in dmCommands.js, never inside a spell's own name): two blows at one target are one attack; in a fight an action plus a bonus or free move is `{type:'turn',steps:[a,b]}`, played by `wholeTurn` while the turn is still the hero's; anything more resolves the first move, with a 'Not this turn: "…" must wait for your next turn' line ('One thing at a time' out of fights).
  - `turnLeft(hero,game)` goes to the Dungeon Master as `turnResources.left` (with `attacksPerAction` and `actionSurge`) and into `context.now`. The Cast… picker offers only spells `castableNow` accepts. The opening attack stays a turn of its own (house rule).
- Speaking to the Dungeon Master (`turnMemory.js`, `verify-direct.cjs`): the DM switch beside the message box, or a message starting "DM," / "(ooc)", sends `context.outOfCharacter` (`canRewind`, `lastTurn`); the server answers out of character, changes nothing, and may return `rewind:true`, and `fault:true` when the player reports, or the DM admits, something the game got wrong (the game then offers to tell the host). `Adventure.act(action,conversation,random,{from})` then applies the exchange to the state remembered before the player's last turn (`rememberTurn`/`turnToRewind`: one turn deep, in memory only, never at a shared table). The exchange is an ordinary no-action turn (`conversation.direct`), so it shows in the feed and the journal. When the Dungeon Master cannot be reached, `offline()` in `DungeonMaster.js` tells the host what to start and a guest only that it is not answering (the old "open your private AI setup window" confused phone players).
- Typing on phones (`webLayout.js`): `#root` is pinned to the visual viewport (`--questbound-height`, `--questbound-top`), so the message box rests above the keyboard on Android and iOS. While the message box is focused on a touch device (`touchKeyboard`), `DungeonMaster` reports `onTyping`: the action row, the Suggestions strip, feed header, bottom tabs and (on short screens) the HUD and strips step aside, and the feed stays on its last lines when its height changes. Controls beside a field carry `dataSet={{keepfocus:'true'}}` so a tap does not blur the field first (a blur closes the keyboard, moves the control and loses the tap). Fields in scrolling pages are scrolled into view when the visible height shrinks; dialogs (`data-qb=scrim`) are sized to the visible area. Test by focusing a field and resizing the viewport to about 375×400.
- Lands and maps (`mapRules.js`, `mapLayout.js`, `mapArt.js`, `AdventureMap.js`, `verify-regions.cjs`, `verify-map-layout.cjs`): every written story has its own `story.geography` (where its three starting places lie and which are joined: a line, a fork or a loop), made by `makeGeography` from the story writer's `layout` or from the story id; a save without one keeps the old fixed triangle (`mapCoordinates`). The writer also gives the land a name and a terrain (`story.region`, `story.terrain`; `terrains`), a kind for each of the three places, up to six `landmarks` that `freshStoryGame` puts on the map as unvisited places (`maxLandmarks`), and one or two `lands` beyond this country (`farLandPlaces`: each a region `r1`/`r2` with one known place 15 to 300 miles from the start, joined to it by a road). Places lie a little off their compass bearing (seeded, repeatable). Regions: the home region plus `game.world.regions` (`r1`…, at most 7); a place carries `region` and inherits it from where it was found; the DM's `discovery.region` ({name, terrain}, miles up to 300) opens a new land, and a sequel turns the earlier country into a region of its own. `regionLayout(game,w,h,{region})` lays out one region's sheet and returns `exits` (roads to other regions, drawn to the edge and tappable); `regionMapSvg` draws it to suit the terrain (`mapThemes`: sea along a coast, a river, ranges, woods, pools, cavern walls, all seeded). Long roads are walked eight hours a day (`travelRoute`). `regionLabels` names what fits; `RegionSheet` zooms and `Full map` opens it in a dialog.
- Reactions to the hero's kind (`relationshipRules.js`, `verify-regard.cjs`): `speciesRegard(game,id,hero)` is each person's view of the hero's species (kin, warm, curious, indifferent, wary, scornful, with a reason): written by the story writer or the DM (`regard` on the NPC or person) or drawn from who they are and how that species is commonly met (`reputations`, seeded; a human among humans is indifferent). It sets the first impression (`firstImpressions`, `introducePerson(game,sketch,hero)`), sways Persuasion, Deception and Performance aimed at that person (`regardSway`: +2 to −3, until they are won over), reaches the DM as `regardsYourKind`, and shows in the People panel while it still says something true.
- Portraits and gender (`worldArtRules.js`): NPCs and people carry `gender` (woman, man, other) from the writer or the DM; without it `genderOf` reads their appearance (a hero's description, then backstory). A woman's portrait description opens by saying she has no beard, any facial hair written into it is cut, and her art id gets `-w` so portraits painted before this are painted afresh. Never write a beard into a woman's appearance (the built-in captain once had a "beard ring").
- The story log (`storyLog.js`, `journalRules.js`, `verify-story-log.cjs`): `game.storyLog` holds one short line per major event (place found, reached or returned to, person met, joined or lost, fight begun and how it ended, deaths, grudges and debts, gold and finds, rests, levels, the end of the tale), worked out by `storyEvents(before,after,hero,{action})` and appended by `withStoryLog` (in `settleTurn`, see Server turns); level-ups and new chapters append their own lines. The Log tab shows it newest first; the engine's raw lines sit under "Latest rolls and rulings".
- Inventory and descriptions (`Inventory.js`, `ActionGuide.js`, `descriptions.js`, `verify-descriptions.cjs`): the Inventory tab shows equipment slots around the hero's portrait and everything carried; every item, action chip and spell has a description (`itemDescription`, `actionDescription`, `spellSummary`), and the check fails if anything is left with a generic one. Loot items carry the DM's `note`. `game.wield` (set by Take in hand) makes a carried weapon the main one (`gearedHero` → `equipment.wield` → `weaponAttacks`). Magic items are attuned there (`attuneItem`, at most 3; the oldest gives way; at a table the `attune` campaign edit). The ⓘ chip at the end of the action row opens the action guide.
- The story's main foe (`storyFoeStats` in `storyRules.js`): a written story gets `foeStats` when it begins (18 HP, AC 12, +3, 1d6+1 at level 1, growing with the hero's level; type from the writer's `foeDamageType`); stories from before keep the lighter default. Against more than one hero it is scaled to the side (see A foe against a bigger side). `node balance-check.cjs --foe story` simulates it.
- Long tales (`storyRules.js`, `adventureRules.js`, `dmContext.js`, `verify-chapters.cjs`): a written story has `chapters` (two to six of {title, goal, turn}; `story.chapter` is the one under way) and `leads` (`l1`…`l4`, each {title, hook, done?}); `questState(game)` reads where it stands and `currentGoal` what to do now. The Dungeon Master gets `context.quest` (the chapter under way, what achieving it reveals, the next one, open leads) and never the later chapters (`context.story` is sent without them). It moves the tale on with the choice `story-advance` (the engine's `advanceChapter`: log lines, journal entries, a world fact) and closes a lead with `lead-done:<id>`; `story-complete` is offered and accepted only in the last chapter. Neither is ever a chip (`quickActions` skips them). Finishing a chapter, a lead or the tale is worth experience (see Experience and levels); `advanceChapter` no longer touches levels. Each written tale has a `hoard` ({item: a catalogue id, name, note}) that its foe carries; `tidyStory` drops an unsound one and the Dungeon Master is not shown it. The feed shows chapter, lead and level lines as cards (`describeEvent`), the Quest tab the chapter, the aim and the leads (the player can tick a lead too), and a new chapter is announced with the `area` cue. Stories without chapters play as before. `offeredChoices` keeps the DM's choices to thirty (the server refuses more).
- People speak first (`greetings.js`, `DungeonMaster.engage`, `verify-greetings.cjs`): the Speak chip opens the conversation and asks the Dungeon Master for a scene moment in which only that person speaks (`greeting(game,id,hero).cue`); the stand-in line (`greetingPools`, chosen by grudge, attitude, companionship, then their view of the hero's kind) is used when the DM cannot be reached. `shouldGreet` keeps someone who spoke in the last turn from greeting again, and nobody greets in a fight. The greeting is a trigger turn: no player line, not remembered for rewinds. At a campaign table the greeting is a server turn (`table.turn(scene,{npcId,greet:true})`; `resolveTurn` in server-turn.cjs checks `shouldGreet`, works out the opening itself with `greeting`, keeps only that person's lines and settles a trigger turn); scene cues are still skipped there (`table.joined`).
- Talking one on one (`speakingPeople` in playbackRules.js, `oneOnOneInstructions` in dm-server.cjs, `verify-social.cjs`): with more than one person present, a conversation sends `conversationWith.oneOnOne` (the "Just you two" / "Everyone here" switch in the conversation header, per device, back to Just you two for each new conversation). The server then allows only that person to speak and no new person to be introduced (never on a scene cue). Anyone addressed answers in their own words, even someone hostile or grudging (curt, refusing, threatening, but never silent or walking off), and words never forgive a grudge. During a brawl `conversationParticipants` comes from `speakingPeople`, so those fighting may shout, plead or yield (their deeds still come only from the game). The Speak chips keep to `conversationPeople`, so a fight has no conversation screen.
- Suggestions (`suggestions` in the DM reply, `cleanSuggestions` and `suggestionInstructions` in dm-server.cjs, `replyIdeas` in greetings.js, `verify-social.cjs`, `verify-greetings.cjs`): every reply carries 0–3 short first-person things the player might say next (last property so narration streams first; required; empty out of character). The server drops OOC/DM lines, HP figures, button talk, repeats of the player's words, duplicates and lines over 110 characters, and never refuses a reply over them. `settled()` in dm-intent returns []. The play screen shows them in an Actions | Suggestions tab strip above the message box (wrapped chips, never a sideways scroll; it never switches tab by itself; keys 1–3 fill while it is open). A tap fills the box with keepfocus and never sends. Hidden while typing on touch, out of character, dead, dying, or during another's turn. When the latest turn has no DM suggestions for this device (another player's turn, a reload, offline), `replyIdeas(game,hero,personId)` stands in (seeded per turn; none in a fight, dying, dead or with a spell waiting). Suggestions live only in the device's memory: never saved or synced (a campaign turn returns them without storing them).
- Stories as background jobs (`story-jobs.cjs`, `writeStory` in `dmConnection.js`, `verify-story-jobs.cjs`): the game asks for a story once with `context.job` and then asks after it with `context.mode:'art'` plus `storyJob` every three seconds; see AI-SETUP.md. The story writer's effort is the host's choice in `.questbound-story-effort` (`high` since 2026-10-02, the host's explicit request: do not lower it to save time). A tale takes about three minutes at that effort; `StoryLoading` says so after twenty seconds.
- A party at the shared table (`partyRules.js`, `verify-party.cjs`; 2026-10-03, stage one of a real party): the host chooses "Everyone brings a hero" (SharedTable.js) and each player who joins brings their own hero (up to four, `maxPartySize`; a shared-hero campaign lets its members control one hero instead). The world is shared; each hero's own state (`heroFields`: draughts, pack, slots, resources, deeds, experience, buffs, Shield and the last hit, dying or death...) lives in `game.party.members[seat]` (each member's opaque per-campaign seat, `seat-<16 hex>`, never their account id; `campaigns.cjs` gives older tables seats on first read) with their sheet, hit points, `status` (up, down, dead) and `stats` (AC, HP, from the geared hero: `statsOf`). A snapshot has one hero in the lead; the campaign server sends every member the table with their own hero in the lead (`partyView`), so the rules engine always plays one hero. `settleParty` reads the lead's state back into the members; `canonicalParty` is the same from every point of view. Foes strike any standing hero (`partyTargets`/`pickFoeTarget`; companions draw a quarter when present; nothing changes without a party) via `foeHitsPartyHero` (their AC and HP, resistance, then a subclass ward, which works on another hero's turn too; at 0 down and dying with `fight:true`, killed outright past their maximum). `fallAtZero` marks `fight` on a fall in a fight: in a party the fight goes on for the others (`stageAfterFall`), unless nobody is standing; a hero fallen in a brawl lies dying while the others fight on. A down hero rolls death saves on their own turn while the party stays where it is (`party.stage`); another hero can give them a draught (`give-potion` with `target:'party:<id>'`, a Revive chip). Every living hero (down ones too, not the dead) gets their own full experience award from their own level for each fight won, chapter, lead, place and tale end (`withExperience`; `partyVictory` is gone); `xp` is a hero field, `xpTally` a world field, and each device's Level up appears from its own hero's xp. Saves accept a party (`validParty`) and any encounter level in one; leaving makes the adventure solo at the hero's own level (`soloFromParty`, the foe back to its numbers for one hero). The Dungeon Master gets `context.party` (name, kind, class, level, condition) and the PARTY instruction: never speak or act for another player's hero. Turns by others show the player's table name in the feed. Stage two (2026-10-03, asked for by the host; `verify-party-turns.cjs`): fights go in turns. `adventureStep` sends every party game through `partyStep`: the first move of a fight (the opening attack) is anyone's; then `beginPartyFight` rolls initiative for every standing hero and the foe (or each person in a brawl, `npc:<id>`) and keeps the order in the shared world as `game.turnOrder` ({order:[{id,init}], at, round, dodging}; `validTurnOrder` in adventureStorage.js). A hero acts only on their own turn (out of turn the engine and the campaign server refuse, `dmChoices` offers only `party-pass`, `commitDmTurn` refuses any action; talking is free). The engine's turn options `foeWaits` (a hero's turn ends without the foe answering; the result says `turnOver`/`dodged`) and `partyFoe` (the foe's own turn: companions first, per-target Dodge and Blur, the foe keeps fighting while anyone stands) do the work; `passTurns` hands the turn on and plays the foe's turn (on the campaign server, with its dice) from a standing hero's point of view; lines about another hero are told by name (`toldOf`). A hero who took the Dodge is harder to hit until their next turn; a spent action stays with the hero whose turn it is (`settleParty` keeps it as `members[id].turn`); a down hero rolls their death save on their turn and the party stays where it is; a hero who joins mid-fight takes the last place; a won or fled fight drops the order. The host may always pass a hero's turn; any other member may once the turn has run 90 s, or at once when that hero's player has not been seen for 15 s (`party-pass`, the Skip chip; `turnClock` in `campaigns.cjs`, kept on the server and not in the snapshot; otherwise 403). Only `direct===true` is talk to the Dungeon Master out of turn. A party member who is down blocks travel (`downPartyMember`/`travelError` in mapRules.js); a member who falls or dies keeps the table valid (`validWildFight`, `validFoeAllies`, `validNpcCombat`), the others fight on (`partyFightsOn`), and `partyAftermath` releases a fallen hero's holds at once and clears marks once the fight is over (`verify-party-falls.cjs`). The play screen shows whose turn it is (`turnOrderView` in encounterRules.js: the action row's "<Name>’s turn" or "Your turn" heading, the fight banner, "<Name>’s turn." in the feed) and `PartyPanel.js` (in the table bar) shows every hero's hit points and, in a fight, the order with the foe. Healing spells reach the other heroes (`request.partyTarget` from "I cast Cure Wounds on Bram", `partyHeal` in spellRules.js, a Cast… chip per hurt friend; the mass healing spells heal the whole party), and so do buffs (see Spells for friends). Not yet: concentration saves for heroes struck on another hero's turn, a per-device Shield setting for heroes struck during another's turn (they get the default, on), and a campaign route for starting the next tale or a new story at a table.
- Tales written ahead (`tale-pantry.cjs`, `topUpPantry`/`aheadOpenings` in dm-server.cjs, `verify-tales-ahead.cjs`; 2026-10-03, to start as fast as Old Greg's Tavern without lowering the story writer's effort): the Dungeon Master keeps finished tales in `.questbound-tales/` (git-ignored; under QUESTBOUND_DATA when hosted): two for Let fate decide and two for Easy to get into and one for every written opening (not Your own tale, not the Skirmish), written at the host's story effort by `generateAdventure` with `context.ahead` (no hero known: the hero is only "you", and the people's `regard` is dropped so `speciesRegard` works it out for the real hero). A tale request that is not the next tale in a region and has no idea takes the oldest stocked tale and answers `{story}` at once (about 6 s to the play screen instead of about 3 minutes); its replacement is written at the asker's cost (their guest label and allowance), then the host's writer goes on until the stock is full (`topUp(openings,write,then)`), one tale at a time, pausing ten minutes after a failure. Stocking starts on any live turn. The stock is about nine cents to fill. `revision` 3 (bump it with dm-server's `loadPantry` literal when the module changes). Files are `<opening>-g3-<uuid>.json`; tales from an earlier `generation` are removed when the pantry is made (raise `generation` when the story writer's output changes shape).
- Your own tale (`adventureIntros.json` `idea`, `IdeaBox` in AdventureIntros.js, `ideaInstructions` in adventure-generator.cjs): the first card in the list (then Easy to get into, then Let fate decide; `App.js` selects Easy to get into by default, never the idea card) where the player writes what they would like to play (8 to 300 characters; Begin stays "Write your idea first" until then), sent as `context.idea`; before the next tale in a region the same box is an optional wish. The writer builds the tale around it, treats it as a wish never an instruction, keeps Questbound's own world (another work's names become its mood with our own people and places), turns other genres into their fantasy counterpart, and stays within the 16+ rating. Ideas are always written fresh (about 3 minutes).
- Easy to get into and varied openings (`adventureIntros.json` `easy` with `errand:true`, `errandInstructions`/`errandDirections`/`openingScenes`/`errandSchema` in adventure-generator.cjs, `validErrand`/`errandPlaces` in storyRules.js, `verify-residents.cjs`): the second card starts the hero with orders from someone with authority (keeper). The writer returns `errand` {title, task, place (a landmark's exact name), reward, threat {template, name, appearance, ally|null}}. `freshStoryGame` makes that landmark a lair held by the threat: below level 3 a pack or the orc becomes a lighter kind; an ally only from level 2 and never of the same kind; a misnamed place falls back to the first risky landmark. It keeps `story.errand` {title, task, place, reward} and adds "Your orders" to the opening journal entry. Chapter 1 is the errand (the writer's instructions), and the DM's ERRAND paragraph hands over the reward with loot once the place is `cleared` (knownPlaces) and the hero reports back. Every tale also has `residents` (two at the start, so the opening scene is never two people alone), and Let fate decide, Easy to get into, the next tale and ideas that do not set their own scene get a random `openingScene` (`openingScenes`, 12). Opening lines may be spoken by residents at the start (`residentN` → their n-id). Grapple and Shove (`grapple`, `shove`, `ally-grapple:N`, `npc-shove:<id>`; `{unarmed:'grapple'|'shove'}` on encounter-attack/npc-attack): an Unarmed Strike with no attack roll, the creature saves with the better of Strength or Dexterity against 8 + Strength + proficiency (`unarmedDC`), only against a creature no more than one size larger (`creatureSize`/`withinGrip`: Small halflings, gnomes and goblins; the dire wolf and giant spider Large; story foes by what they are), one attack of the action (Extra Attack follows with a weapon that leaves a hand free). What these leave on a creature is `game.marks[key]` (`foe`, `ally:N` or a person's id: `prone`, `grappled` by hero id, `sapped`, and spell conditions under `spells`): a prone creature gives melee attacks advantage and shots and throws disadvantage, has disadvantage itself, and gets up at the start of its turn unless held (a grappled creature's speed is 0); a grappled one has disadvantage at anyone but its holder; a hold ends when the holder drops or swings a two-handed weapon or a second weapon (`letGo`, free); Sap is spent on the creature's next attack and ends anyway before the hero's next turn (`sapsEnd`); `endHeroTurn` closes what lasts a turn; `fightOver` clears it all when the fight ends. The Attack… picker shows each weapon's mastery in its detail and Grapple/Shove (with their DC) under Melee; the off-hand chip appears after a Light weapon's attack ("Bonus" or "Nick"); typed "I grapple the bandit", "I shove him to the ground", "I stab with my other dagger" work ("I grab the key" stays a sentence for the Dungeon Master). The Dungeon Master is told the hero's masteries (`attackOptions.masteries`) and how creatures stand (`fightConditions`). Spells must be named: `spellNickname` resolves initials or a word that fits one known spell, a closing full stop is ignored, and the DM server turns an unnamed cast into a question (`spellNamed` in `dm-server.cjs`). Story-fight spell targets match loosely (`storyFoeNamed` in `spellRules.js`).
- Spells (`spellRules.js`, `dmCommands.js` cast parsing, `quickActions.js` `spellActions`, `verify-spell-routes.cjs`; the host's "Couldn't cast detect magic", 2026-10-04):

  - Narrated spells. Sensing and everyday spells (`narratedSpells`, Detect Magic included) are spent by the game and described by the Dungeon Master in one telling, with no ruling to wait for.
  - Rituals. Out of a fight a ritual spell needs no slot (10 minutes) unless a slot is named. Slots can be named "level 2 slot", "at 2nd level", "using a 3rd-level slot" or "at level 3".

  - People. Spells aimed at people use `personDefenses`: their own AC, and saves by toughness.
  - Rolled spells. `automaticEffects` rolls the damage spells; `true-strike` swings the hero's weapon with their spellcasting ability.
  - Conditions. Conditions from spells (`spellConditions`: Sleep (as in SRD 5.2: a failed save leaves the creature `drowsy`, a second failure at the end of its next turn `asleep`; undead, constructs and elves are `sleepless`), Hold Person/Monster, Hideous Laughter, Command, Entangle, Web, Faerie Fire, Blindness, Color Spray, Charm Person/Monster, Fear, Bane) live in `game.marks[key].spells` ({id, cond, by: hero id, dc, save, rounds?}; `validMarks`).   - Buffs. Bless, Heroism, Guidance, Resistance (`concentration.damageType`) and `game.buffs` (Mage Armor, Barkskin, Divine Favor, Shillelagh) on the caster; on friends see Spells for friends.
  - New fields. `buffs`, `speciesUsed`, `lastHit`, `hurtBy` and `shieldUp` are hero fields at the shared table (partyRules `heroFields`). `fightOver` and a long rest clear them.
  - Checks. `verify-spell-routes.cjs` replays every catalog spell through the real routes in a written story (and every use-again and move chip, Bless and Aid at the shared table, and the Shield setting) and writes SPELL-COVERAGE.json; `verify-spell-effects.cjs` checks the lasting, area and friendly spells. A grudge outweighs a bond. A grudge can be forgiven, never cheaply: it has a weight (`grudgeWeight`: blood when their family, beloved or own kin was killed, else grave), `grudgeSince` (the story log id when sworn) and `amends` (0–6). `forgivenessOf(game,id)` says what forgiving needs: grave 2 amends and 1 day, blood 3 and 2 days, one fewer with a bond, one more for a grudge sworn again after an earlier forgiveness (`forgave` record: {grudge, weight, memory}).
